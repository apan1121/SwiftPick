# LuckyDraw 開發實作計劃（落地版）

## 背景與目標
- 背景：基於現有 Vue 3 + Webpack 5 專案，實作支援 5 萬筆名單的抽獎系統。
- 目標：完成獎項與參與者匯入/管理、透明化名單展示、流暢抽獎動畫、公平隨機、中獎結果管理與匯出、IndexedDB 本地持久化。

## 里程碑與時程（估）
- M1 架構與頁面骨架（1-2 天）：路由、四頁骨架、導覽條、頁面跳轉。
- M2 狀態管理與資料結構（1-2 天）：Vuex modules（prizes/participants/drawing）。
- M3 匯入/解析與驗證（2-3 天）：Textarea/CSV 匯入、重複檢測、錯誤提示、測試資料生成。
- M4 名單虛擬清單（2 天）：@tanstack/vue-virtual 網格清單、搜尋與即時高亮。
- M5 抽獎動畫與 RNG（3-4 天）：亮燈節奏、加速/減速/停止、去重與名額處理、音效。
- M6 結果管理與匯出（2 天）：結果頁、統計資訊、CSV 匯出、重抽/清空。
- M7 持久化與最佳化（2-3 天）：IndexedDB 分批寫入/載入、效能微調、錯誤處理。

## 路由與頁面（對應 Wireframe）
- 路由規劃：
  - `/prizes` → PrizeSetup.vue
  - `/participants` → ParticipantList.vue
  - `/drawing` → DrawingBoard.vue
  - `/results` → Results.vue
- 導覽：頁面上方步驟導覽（完成/進行中/待定狀態切換）。

## 狀態管理（Vuex 4）
- 模組命名：`luckyDraw`，掛載至 `createStores(['common', 'luckyDraw'])`
- 資料結構：
  - Prize：`{ id: string, name: string, quantity: number, winners: string[] }`
  - Participant：`{ id: string, name: string, nickname: string, isWinner: boolean }`
- modules 拆分：
  - `luckyDraw.prizes`：獎項 CRUD、數量檢核、寫入 winners。
  - `luckyDraw.participants`：名單導入/查詢/重複檢測、搜尋索引。
  - `luckyDraw.drawing`：當前獎項、動畫狀態、速度、歷史中獎紀錄。

## 服務層（services/）
- `csv.js`：PapaParse 解析、格式驗證、錯誤彙整；textarea 與 CSV 上傳共用。
- `random.js`：`crypto.getRandomValues` 隨機抽樣、去重、可選抽樣 log（透明性）。
- `storage.js`：IndexedDB 封裝（分批寫入/載入、錯誤回退）；啟動時自動載入。

## 名單虛擬清單
- 套件：`@tanstack/vue-virtual`（既有依賴）實作網格虛擬化。
- 行為：支援即時搜尋、可標示 `highlighted` 與 `winner` 樣式；僅渲染可視範圍。

## 抽獎動畫與邏輯
- 動畫節奏：
  - 初始 50ms → 加速至 20ms → 減速至 200ms → 停止。
  - 使用 `requestAnimationFrame` 與 CSS `transform`/`will-change`。
- 隨機：`crypto.getRandomValues`；避免重複中獎；多名額（quantity > 1）批次抽取或逐一抽取並更新狀態。
- 控制：開始/暫停/加速/重新開始；當前獎項剩餘名額即時更新；音效事件掛載。

## 結果管理與匯出
- 頁面：依獎項分類顯示中獎者、展開/收合、搜尋中獎者。
- 匯出：使用 `json-2-csv` 匯出單一獎項或全部結果。
- 操作：重抽（單獎項/全部）、清空結果。

## 持久化（IndexedDB）
- 內容：participants、prizes、results；版本化結構；大資料分塊寫入、延遲提交避免主執行緒阻塞。
- 啟動：自動載入；資料不存在時可載入示範資料（選項）。

## 效能策略
- 渲染：虛擬化、`v-memo`/`shallowRef` 應用於大集合；避免深層響應。
- 匯入：PapaParse chunk 解析、批次 commit；UI 顯示進度。
- 動畫：僅切換 class、transform，加速用變數調整步進；避免頻繁重排。

## 風險與應對
- 大量渲染卡頓 → 虛擬化 + 分批渲染；必要時降級為分頁。
- 記憶體壓力 → `shallowRef`、釋放監聽、按需載入頁面。
- 隨機公平性爭議 → 使用 CSRNG、提供抽樣 log/校驗說明。
- 瀏覽器儲存限制 → 分段匯入、壓縮/精簡暱稱欄位；必要時提示使用者。

## 驗收標準
- 5 萬名單載入後操作流暢（滾動、搜尋、抽獎無明顯卡頓）。
- 抽獎動畫符合節奏規格，結果公平且不重複（同一獎項）。
- 獎項與參與者支援 textarea 與 CSV 匯入，錯誤可視化提示完整。
- 中獎結果可依獎項檢視與 CSV 匯出；資料可於重整後保留（IndexedDB）。
