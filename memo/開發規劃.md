# Vue 抽獎網站開發規劃

## 專案概述

基於現有 Vue 3 + Webpack 5 架構開發的抽獎系統，支援五萬個名單的抽獎網站，具備以下核心功能：
- 獎項和參與者名單輸入（支援 textarea 和 CSV 匯入）
- 透明化名單顯示防止作弊
- 動畫抽獎效果（隨機亮燈）

## 技術架構

### 前端框架 (基於現有環境)
- **Vue 3 + JavaScript**：使用 Options API 和 Composition API 混合開發模式
- **Webpack 5**：自定義配置，支援 DLL 優化和多執行緒建置
- **SCSS + Bootstrap 4**：樣式系統，禁用 Tailwind CSS

### 核心技術挑戰
1. 五萬筆數據的渲染性能優化
2. 大量 DOM 元素的記憶體管理
3. 流暢的抽獎動畫效果
4. CSV 文件解析和數據處理

## 功能模組設計

### 1. 數據管理模組
- **狀態管理**：使用 Vuex 4 管理全域狀態 (按照現有架構)
- **數據結構**：
  ```javascript
  // Prize 物件結構
  {
    id: string,
    name: string,
    quantity: number,
    winners: []
  }

  // Participant 物件結構
  {
    id: string,
    name: string,
    nickname: string,
    isWinner: boolean
  }
  ```
- **本地存儲**：使用 IndexedDB 儲存大量數據
- **CSV 處理**：使用 PapaParse 進行 CSV 解析和驗證

### 2. 輸入介面模組
- **獎項設定頁面**
  - 支援 textarea 一行一筆輸入
  - 支援 CSV 文件上傳
  - 獎項數量設定
  - 數據預覽和驗證

- **參與者名單頁面**
  - 支援 textarea 一行一筆輸入
  - 支援 CSV 文件上傳
  - 名稱和暱稱欄位
  - 重複名稱檢測

### 3. 名單顯示模組
- **虛擬化滾動**：使用 vue-virtual-scroller 處理五萬筆數據
- **網格佈局**：響應式設計，使用 SCSS + Bootstrap 4 網格系統
- **搜尋篩選**：即時搜尋參與者
- **透明化展示**：確保所有人都能看到完整名單

### 4. 抽獎動畫模組
- **隨機亮燈動畫**：使用 Vue Transition + CSS 動畫
- **抽獎演算法**：確保公平性的隨機選擇
- **動畫控制**：開始、暫停、加速功能
- **結果展示**：中獎者高亮顯示和音效提示

### 5. 結果管理模組
- **中獎記錄**：按獎項分類顯示
- **重複抽獎防護**：防止同一人重複中獎
- **匯出功能**：將中獎名單匯出為 CSV
- **統計資訊**：顯示抽獎統計數據

## Vue 特有優勢

1. **響應式系統**：Vue 3 的 Proxy 響應式更適合處理大量數據變更
2. **組合式 API**：更好的邏輯複用和代碼組織
3. **編譯優化**：模板編譯時的靜態提升和樹搖優化
4. **完整生態**：Vue Router、Vuex、Webpack 5 的完整開發工具鏈

## 性能優化策略

### 1. 渲染優化
- **虛擬化滾動**：只渲染可見區域的元素
- **v-memo**：緩存大列表的渲染結果
- **shallowRef**：對大數據使用淺層響應式

### 2. 記憶體優化
- **分塊載入**：將五萬筆數據分批處理
- **及時清理**：清理不需要的事件監聽和計時器
- **組件懶載入**：按需載入大型組件

### 3. 動畫優化
- **CSS Transform**：使用 GPU 加速的 transform 屬性
- **will-change**：提示瀏覽器即將變更的屬性
- **requestAnimationFrame**：優化動畫時機

### 7. 動畫設計規格

#### 隨機亮燈動畫：
- **初始速度**: 每50ms切換一次亮燈
- **加速階段**: 速度逐漸提升至每20ms
- **減速階段**: 速度逐漸降低至每200ms
- **停止動畫**: 最終中獎者閃爍3次並保持高亮

#### 視覺效果：
- **亮燈狀態**: 金黃色背景 + 白色文字 + 外發光效果
- **普通狀態**: 淺灰背景 + 深色文字
- **中獎確定**: 彩虹漸層背景 + 白色文字 + 放大動畫

## 風險評估與應對

### 主要風險
1. **大量數據渲染性能問題**
   - 應對：實作虛擬滾動和分批載入
2. **瀏覽器記憶體限制**
   - 應對：使用 shallowRef 和及時清理
3. **隨機性公平性質疑**
   - 應對：使用加密級隨機演算法並提供驗證機制

### 備選方案
1. 如虛擬滾動性能不佳，考慮分頁載入
2. 如前端儲存限制過大，提供分段匯入功能
3. 如動畫效果影響性能，提供簡化模式選項
